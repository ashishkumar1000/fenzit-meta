# Web console "Leave" section — Types config + Requests with approvals

## Context

The backend has a complete, live leave API that **no web page consumes today**: the fixed 4-type leave catalog (Earned/Sick/Bereavement/Comp-Off) with a values-only `PATCH /attendance/leave/types/:id`, the owner leave-requests list `GET /attendance/leave` (status filter + keyset pagination), and owner approvals `POST .../approve|reject|revoke` (currently mobile-only). The owner logged into the web console, we surveyed every section, and they chose: a **new "Leave" sidebar section** (placed between Holidays and Attendance) with **two tabs — Types + Requests — including approve/reject/revoke actions**. Zero backend changes; this is pure frontend work in fenzit-web.

## New files

### 1. `src/features/admin/leaveApi.ts` — resource module (model: `companyApi.ts` patterns)
- `LeaveTypeRow` interface mirroring the BE `LeaveTypeView`: `id, code (string|null — null = legacy remnant), name, accrualMode ('monthly'|'annual'|'none'|null), accrualDays, carryForward, allowOverBalance, paid, enabled, configurable`
- `fetchLeaveTypes(token)` → `GET /api/v1/attendance/leave/types`
- `patchLeaveType(token, id, values)` → `PATCH .../types/:id`, body carries **changed fields only** (5 allowed: `accrualDays`, `carryForward`, `allowOverBalance`, `paid`, `enabled`)
- `LeaveRequestRow` — reuse the existing `LeaveRow` shape (`companyApi.ts:94`); add `fetchLeavePage(token, { status?, cursor?, limit? })` → `Page<LeaveRow>` (`{ data, nextCursor, hasMore }`)
- `approveLeave(token, id)` / `rejectLeave(token, id, reason?)` / `revokeLeave(token, id, reason)` → the three POSTs (reason omitted when empty on reject, required on revoke)

### 2. `src/features/admin/leaveLoaders.ts`
- `adminLeaveLoader` — `requireConsoleRole(request, ["owner"])`; reads `?tab=` (default `types`) and `?status=`/`?cursor=` on the requests tab; fetches only the active tab's data; returns `{ state: "ok", … } | { state: "failed" }`; auth errors → `clearSession()` + `redirect("/login")`
- `adminLeaveAction` — intents `save-type` / `approve` / `reject` / `revoke`; validates per type mode + state machine client-side, calls the API, returns plain `{ kind, state: "done" | "error", message? }` (never throws except auth redirects); unknown failure copy via `messageForError`, with call-site branching on `error_code` for the known cases (`LEAVE_TYPE_NOT_CONFIGURABLE`, `LEAVE_NOT_PENDING`, `LEAVE_NOT_REVOKABLE`)

### 3. `src/pages/AdminLeavePage.tsx` + `AdminLeavePage.module.css` (tokens only)
Own header (breadcrumb + greeting, attendance-style) + `Tabs` (`components/Tabs.tsx`): **Types** (first tab, bare path) | **Requests** (`?tab=requests`).

**Types tab** — one `SectionCard` per configurable type (4 fixed types by code):
- **earned / sick (monthly)**: accrual rate number input (step 0.5, min 0), Carry-forward toggle, Allow over-balance toggle, Paid toggle, Enabled toggle
- **bereavement (annual)**: annual grant number input, Paid, Enabled (no CF/over-balance — BE rejects them on non-monthly)
- **comp_off (none)**: Paid + Enabled only (no accrual input — BE rejects `accrualDays > 0`)
- Per-card `useFetcher` save button, enabled only when dirty; disabled legacy remnants (if any) listed read-only below
- Errors inline `role="alert"`, success `role="status"` (repo pattern: no toasts)

**Requests tab** — status filter chips as links (`?status=` ∈ All/Pending/Approved/Revoked/Cancelled/Rejected — the BE filter uses the same derived status as display), cursor pager (customers-page model), table columns: Employee (`employeeName ?? employeeCode`), From, To, Days (`workingDays of totalDays`), State (`StatusBadge` — already tones all 5 states), Reason, Actions:
- pending rows → **Approve** (confirm dialog) + **Reject** (dialog, optional reason)
- approved rows → **Revoke** (dialog, **required** reason)
- Dialogs follow `AddCustomerDialog.tsx`: native `<dialog>` + `useFetcher.Form`, `key` remount per open, inline error line, close on done

### 4. `src/pages/AdminLeavePage.test.tsx` (bun:test + `testing/fetchMock.ts`)
Render the real routes table via `createMemoryRouter`; `respondDefault` branches for `/leave/types`, `/attendance/leave`, and the three POSTs (unmatched URLs throw loudly). Cover: both tabs render; types wire contract (PATCH method + changed-fields-only body); comp_off has no rate input; CF/over-balance hidden on non-monthly; remnant renders read-only; status chip navigations hit `?status=`; approve/reject/revoke POST bodies (reason present/omitted); 409/422 error copy; auth-error redirect.
