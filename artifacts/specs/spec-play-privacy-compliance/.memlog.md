topic: Google Play privacy compliance: in-app policy/terms links, in-app account-deletion link, policy content hardening
updated: 2026-11-03T18:29
---

- (decision) Driver is the Google Play User Data policy (support.google.com/googleplay/android-developer/answer/10144311): policy must be linked in-app, account deletion must be reachable in-app AND on a web resource; Google accepts an in-app link that opens the web deletion page.
- (capability) CAP-1 In-app legal links: a person can open the privacy policy and terms from inside the app — tappable Terms/Privacy text on the login screen (the consent point) plus rows on Account & settings — opening https://fenzit.com/privacy-policy and https://fenzit.com/terms.
- (capability) CAP-2 In-app deletion entry: a person can start account deletion from the app — a Delete account row on Account & settings opens https://fenzit.com/delete-account, whose phone+OTP verified web flow completes the request (same URL entered in Play Console's deletion field).
- (capability) CAP-3 Policy content hardening: the published /privacy-policy gains an explicit camera-use sentence, a children statement (not directed at under-13s), and a pointer to the self-serve /delete-account page; last-updated date bumped to the change date.
- (constraint) Play User Data policy is the contract: policy reachable within the app; deletion reachable in-app (link → web resource is Google's accepted form); no native deletion flow, no WebView — the device browser opens the live fenzit.com pages.
- (constraint) Link opening must not break on Android 11+ package visibility — never gate https opens on Linking.canOpenURL (openUrl in src/utils/linking.ts already avoids it); a failed open must not crash the screen (silent guard, same philosophy as openTel).
- (constraint) Tappable text uses React Native accessibilityRole='link' with an adequate touch target; legal copy follows the existing legalCopy.ts plain-English style — only statements the product actually honours today; date bumped via the single LEGAL_UPDATED constant.
- (decision) Non-goals: no native in-app deletion flow; no Play Console Data safety form work (manual, not code); no change to the location prominent-disclosure flow (already compliant); no new legal claims (no M&A/GDPR clauses) the owner has not stated.
- (assumption) fenzit.com/privacy-policy, /terms and /delete-account are the canonical public URLs (verified live 2026-11-03); the app's MoreScreen ('Account & settings') is the settings page the owner means; test timing rule applies — no new tests until the owner confirms the behaviour on device.
- (event) Research pass 2026-11-03: RN docs confirm openURL+catch with accessibilityRole='link', no canOpenURL for https (iOS LSApplicationQueriesSchemes limit, Android 11+ package visibility); Google's account-deletion help (answer/13327111) explicitly sanctions an in-app link that opens the web deletion resource; deletion URL must be functional, prominent, name the listing app, no bounce back to app — /delete-account already meets all four. Approach validated as the standard pattern, not a hack.
- (event) Self-validate pass 1 (coherence): PASS — all three capabilities carry intent+success; constraints rule out real approaches (canOpenURL ban, WebView/native-flow ban); non-goals explicit; success testable.
- (event) Self-validate pass 2 (preservation): PASS — policy-URL verdict, dead-text links, sanctioned link-to-web deletion, camera+children hardenings, Data-safety-form-as-manual-step, test-timing rule all landed in SPEC; wrapper-only drops: none.
- (direction) OWNER DIRECTION 2026-11-03: Delete account in-app becomes a real consent flow — popup informing the user they are about to delete the account, role-specific consequence copy (owner vs employee), no OTP in-app (already signed in), on consent the deletion is filed, on success the app logs out automatically.
- (decision) Owner chose request+review over immediate deletion: in-app consent files the SAME reviewed deletion request (account_deletion_requests) using the JWT identity — no OTP — and the admin console review stays the executor; consistent with the web page's review-by-hand promise and no one-tap company wipe.
- (decision) CAP-2 revised: a signed-in person can start account deletion in the app — role-specific ConfirmDialog states the consequences; consent calls a NEW authenticated BE endpoint (JWT identity replaces the OTP proof; idempotent on an open request); success auto-logs-out (token cleared, stores reset, back to login). The web link is no longer the in-app deletion surface; /delete-account stays the Play Console web resource.
- (constraint) Cross-repo ordering: BE endpoint is additive → fenzit-be merges/deploys FIRST, then fenzit-app switches onto it; app failure path shows a retryable error inside the dialog and does NOT log out on failure.
