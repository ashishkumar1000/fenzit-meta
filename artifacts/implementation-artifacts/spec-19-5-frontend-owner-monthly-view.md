- **Story:** 19-5 (FR-25, UJ-4) — the owner's month-end review: a per-employee monthly summary list with an office filter, tapping through to that employee's `MonthCalendar` (the Epic-18 component's first PRODUCTION host), plus the flag-row deep-link from the 19-4 dashboard that this story was deferred to.

- **Baseline:** fenzo-app at the 19-4 commit (`a006a95`, includes the user's `d5cae2d` TimeField work); fenzit-be at `b210aee`. BE for 19-3 already shipped (a3c8aa8): `GET /api/v1/attendance/monthly?from=&to=&officeId=` per spec-19-1-to-19-3 §D6.
- **Status:** draft → adversarial review (2 lenses) + UX design pass (Sally ruling + DS + a11y) → step-03 triage (§9: 43 findings → all dispositioned) → **frozen for build**.
- **Sources:** epics-attendance-leave.md §Story 19.5 (ACs quoted where they bind); prd.md FR-25 ("The Owner's monthly view opens as a **list of Tracked employees**, each with their month summary: Days worked, Half days, Late count, Leave (days, with half days as 0.5), Weekly offs, Holidays, Worked on holiday, Absent, Checkout missing. ## 2. Design decisions (locked before implementation)

**D1 — Entry + routes.** New tile **"Monthly"** on `AttendanceHomeScreen`, inserted between Today and Leave (verified order there: Today → Leave → Offices → Settings → dev lab), `Tile` idiom: icon `CalendarDays size={20} strokeWidth={1.5}` (in lucide-react-native, verified), `iconBg={colors.status.progress.bg}` with the icon in `colors.status.progress.solid` — **Sally Q1 ruling:** the production AttendanceHome family reads blue = "review people" (Today, Leave, Settings are all progress-bg; `neutral` would sort Monthly with the grey dev-lab tile), superseding the draft's neutral lean. Title "Monthly", subtitle "Everyone's month at a glance" → `navigation.navigate('AttendanceMonthly')`. Renders past the setup gate like its siblings (19-4 D1). Routes in `RootStackParamList` (the 19-4 registration pattern):
- `AttendanceMonthly: undefined` — the list screen (`src/features/attendance/monthly/AttendanceMonthlyScreen.tsx`).
- `AttendanceEmployeeMonth: { employeeId: string; employeeName: string; yearMonth: string; focusDate?: string | null }` — the drill-down host. `yearMonth` REQUIRED (the drill-down opens on the month the list showed — continuity); `focusDate` set only by the flag deep-link (D7), and D7 derives it from the same `workDate` as `yearMonth` — the host normalizes the pair once on params (a mismatched pair is dev-warned and the guard treats `focusDate` as absent).

**D2 — BE additive: `today` on both monthly responses (the one BE change).** `MonthlyResponse` and `MeMonthlyResponse` gain `today: string` (tenant-local `YYYY-MM-DD`, the same `tenantToday` the service already resolves for the `to > today` 422). Why: the FE must clamp a current-month request to `to = today` (the BE 422s a future `to`) and bound the month nav — and the FE never derives "today" from the device clock for range math. `MeMonthlyResponse` gets it in the same change (same service, one extra key; 19-6 consumes it next — recorded so the reviewer doesn't call it YAGNI). FE normalizer treats `today` as **REQUIRED and regex-checked** (the dashboard `date`-echo rule, `normalizeDashboard`) — deliberately NOT optional-absent→null like 19-4's `offices`: the clamp is load-bearing request math, not display enrichment, and the cross-repo order (BE first) means a missing `today` is drift, not an older deployed BE. BE change ships: `monthly-response.model.ts` (+ spec fixtures), both service returns, **`test/attendance-reads.e2e-spec.ts`** (verified: the monthly pins live THERE, not in a monthly-named file — flip both exact key pins `['from','to','employees']` ~line 316 and the me pin ~line 423 to include `today`, and assert `today` equals the seeded tenant's today), `docs/api-contracts.md` rows. No DB change.

**D3 — Data service.** New `src/services/resources/attendanceMonthly.ts`:
- `fetchMonthly(from: string, to: string, officeId?: string)` → `GET /attendance/monthly` with `from`/`to` always and `officeId` RAW (params object; apiClient encodes once — the 19-4 double-encode lesson). No idempotency key (read).
- Request shaping lives in the MODEL, not the screen: `monthlyWindow(yearMonth, today)` → `{ from, to }` = `monthRange(yearMonth)` with `to = min(range.to, today)` (lexicographic compare is chronological on `YYYY-MM-DD`) — uniform, so a past month is a no-op clamp and the current month clamps to today. `today == null` never reaches the fetch (D4's disabled-until-known rule gates it).
- Response type + fail-closed normalizer (the 18-3 fetch-level rule; the whole fetch rejects on ANY violation — never a partial render): `{ from, to, today }` each `YYYY-MM-DD` regex-checked; `employees: EmployeeMonthlyRow[]` — each row `{ employeeId: non-empty string, employeeName: non-empty string, officeId: string | null, officeName: string | null, summary }` where `summary` = the nine FR-25 keys verbatim (`daysWorked, halfDays, lateCount, leave, weeklyOffs, holidays, workedOnHoliday, absent, checkoutMissing`); the six count fields must be non-negative INTEGERS (`Number.isInteger`), the three decimal fields (`daysWorked`, `leave`, `workedOnHoliday`) non-negative finite numbers (17.5 is legal). Unknown shape throws. Re-exported via the resources index.
- Wire truths rendered honestly: rows include history-only/disabled employees with any tracked day in range (FR-28 — no FE filter); `officeId`/`officeName` nullable (an employee with no today-covering assignment); an unknown-but-well-formed officeId → 200 with ZERO rows (a filter is not an entity fetch — no FE existence check).

**D4 — The list screen.** `AttendanceMonthlyScreen`: `ScreenHeader` (title **"Monthly"**, the shared back-header — `DashboardHeader` is rejected because it is refresh-bound (`onRefresh` required) and this screen has NO manual refresh; D9's discipline covers refetching) → `WorkspaceSelector` reused with `officesCount={null}` permanently (**Sally Q2: NO Sites pill** — the dashboard's pill rides the envelope registry for free; here it costs a standing second fetch against D9's budget and adds nothing to a month-end review; the selector label is the parity that matters) → the month nav row → the employee list → sheets.
- **Month nav (host furniture #1):** ‹ › round buttons + the month label, built on `monthlyModel.monthTitle` (moved there so the pane and the list share ONE month-name table — the 19-4 review's no-third-MONTH_NAMES rule). Buttons 44×44 `borderRadius: radius.pill` (the pane's current 40×40 is BELOW `touch.min` — both screens' nav rows get the corrected size; the lab inherits the fix harmlessly). Labels "Previous month"/"Next month" (the pane's existing strings).
- **Default month bootstrap (the echo circle, closed):** the initial `yearMonth` is seeded from the DEVICE clock as declared navigation scaffolding (the lab's `initialYearMonth` idiom — the device clock here picks which month to LOOK at first, never a fetch boundary); when the first echo lands, the canonical default `shiftYearMonth(today, -1)` is computed once — if it differs from the displayed month AND the owner has not navigated (guard ref), the month corrects in the same in-place swap; if the owner already navigated, their choice stands. FETCH windows are echo-derived once an echo exists (`monthlyWindow(yearMonth, today)`); the bootstrap fetch takes the seeded past month's PLAIN range (no clamp — there is no echo yet; a device clock running ahead of the tenant clock would 422 into the honest error posture, recoverable via ‹ — recorded in §10). A clamped current-month window is only ever reached by an explicit › (the "so-far" reading is then the honest one).
- **Month bounds:** › is **disabled** when `today == null` (disabled-until-known — never enabled-and-unbounded; on the drill-down this matters doubly because the day-statuses route does NOT 422 a future range — verified: it validates `from ≤ to`, span ≤ 62 only, so a future month is a silent all-not_tracked grid) and when `yearMonth === today.slice(0, 7)`; ‹ unbounded past (FR-25: "any past month since the module was enabled"). Disabled renders via the Pressable's `disabled` prop + `accessibilityState={{ disabled: true }}` (the house announce idiom).
- **In-flight month/office loads (amended 2026-09-30, user direction):** a PARAMETER load (month switch, office pick) answers with the row Skeleton — the same labelled `<Skeleton rows={6} height={ROW_HEIGHT}>` as first load; the stale rows stand down while it fetches and the label has already swapped, so label and skeleton always describe the same window. The engine exposes `paramLoading` (a param-load-only flag; the echo-correction's follow-up fetch stays silent). **This supersedes Sally Q5's silent-swap ruling** — the user asked for a loader ("can we add some loader while the data is fetching") after watching the silent posture on device; the disabled-chevrons acknowledgment stays. Focus/AppState refetches keep the silent in-place swap (no skeleton), and a failure still reverts the PAIR + shows the fixed copy below.
- **Rows (host furniture #2):** a NEW `MonthlyEmployeeRow` (the AC's "reusing TechnicianPicker's row style" — the STYLE, not the component: `TechnicianPicker` is a single-select picker with a check circle, search and a 240 cap; `EmployeePickerSheet` rows are sheet-bound with no third line; verified neither composes). **Final anatomy (Sally ruling C + DS corrections):** a flat bordered row — `Pressable` (`accessibilityRole="button"`, pressed opacity **0.8**, the FlagStrip idiom), `borderWidth: 1`, `borderColor: colors.borderSubtle`, `borderRadius: radius.lg`, `backgroundColor: colors.surfaceCard`, NO shadow, `flexDirection: 'row'`, `alignItems: 'center'`, `gap: spacing.s3`, `paddingHorizontal/Vertical: spacing.s3`, `minHeight: touch.large` (content-driven ≈72-80px) — trailing `ChevronRight size={18} color={colors.textMuted} strokeWidth={2}` (the FlagStrip affordance the owner learned on Today). Content: `Avatar name size="md"` → a text column (`flex: 1`, `minWidth: 0`, `gap: 2`): **name** `typography.bodyStrong` + `colors.textStrong` `numberOfLines={1}` (the screen-level employee-row ramp — FlagListSheet/EmployeePickerSheet; NOT the picker's `label` role); **chips line**: an atomic-chip row — `flexDirection: 'row'`, `flexWrap: 'wrap'`, `gap: spacing.s2`, each chip an ATOMIC `Text` (`typography.captionStrong`) in its family fg, so a wrap breaks BETWEEN chips, never mid-phrase, and per-chip colour survives (deliberately NOT `Badge` — its docblock fixes that vocabulary to job state; the KpiTile coloured-`visualLabel` precedent carries the look without pills); **caption line**: `typography.caption` + `colors.textMuted`, `numberOfLines={1}`, segments joined " · ", omitted entirely when empty.
- **Summary chips (the AC's text+colour rule):** TEXT + colour ONLY, no icon (the stated FR-25 exception). Zero-suppressed EXCEPT `daysWorked` (always the first chip — the anchor). **Copy (Sally B rhythm × a11y nouns), number-first throughout:** `«n» worked` / `«n» half day«s»` / `«n» late` / `«n» leave` / `«n» absent` / `«n» missing checkout«s»`; the chips line joins with " · ". **Colours (Sally Q3, token-verified):** worked → `colors.status.done.fg` (NOT progress — `progress` and `leave` are byte-identical blue families, and `done` is the house present/worked family: KpiTile checkedIn, the calendar's present), half → `colors.status.scheduled.fg`, late → `colors.status.scheduled.fg` (there is NO `late` token; the Late tile and the Late flag are `scheduled` amber), leave → `colors.status.leave.fg`, absent → `colors.status.cancelled.fg`, missing checkout → `colors.status.checkoutMissing.fg`. Amber-on-amber adjacency (half/late) is accepted — each run self-labels (FR-25's never-colour-alone holds by construction; the calendar ships the same collision). Decimals format via `formatCredit()` in the model (integer → "18", else "17.5"); `formatCredit` is genuinely new (verified: no decimal-credit formatter exists).
- **Caption line** (so all nine FR-25 fields are on the row face): `officeName` when present, then `weeklyOffs` ("«n» weekly off«s»"), `holidays` ("«n» holiday«s»"), `workedOnHoliday` ("«n» worked on holiday" — the a11y pass's top fix: "on holiday" alone reads as LEAVE in Indian English and inverts the fact) when > 0. Zero-suppressed; line omitted when every segment is absent.
- **Row a11y:** ONE focusable element — `accessibilityLabel` on the Pressable, children hidden (`accessibilityElementsHidden` + `importantForAccessibility="noHideDescendants"`), assembled in the model with COMMAS never "·" (TalkBack reads the dot): `«name». «n» worked, «n» half days, «n» late, «n» leave, «n» absent, «n» missing checkouts. «office», «n» weekly offs, «n» holidays, «n» worked on holiday` (zero-suppressed segments omitted; the caption sentence omitted when empty). The exact assembled string is pinned in `monthlyModel.test.ts`.
- **List posture:** rows in a `ScrollView` with content gap `spacing.s3` — deliberate: it matches the Skeleton container gap so the skeleton-to-rows swap does not jump (Sally/DS). First load renders `<Skeleton rows={6} height={ROW_HEIGHT} />` row-shaped, `ROW_HEIGHT` a shared constant with the row (≈72-80); the sheen is built into every Skeleton row (verified). The skeleton block carries `accessibilityLabel="Loading attendance"` (one string, this screen). `employees.length === 0` → `EmptyState` (icon `Users`, title "No attendance to review", description "No one has tracked days in this month. Try another month or office." — no "yet": ‹ is unbounded, so a past month will never fill in) inside the plain ScrollView (dashboard parity: top-aligned, not centered).
- **Load engine (seq-guard + pair revert):** `useMonthlyData` is seq-guarded latest-wins (the `useMonthlyStatuses` seq shape): only the LATEST request may commit rows or touch state — an older-resolves-late response (fast ‹ › interleaving) never commits and never reverts. On failure the revert restores the last-good **PAIR** `{yearMonth, officeId}` — the pair the on-screen rows actually came from — never one axis (a single-axis revert would pair "August" with All-offices rows).
- **Error copy:** refetch/param failures render the FIXED copy "Couldn't load the monthly view. Check your connection and try again." — never `err.message` (the normalizer's throw strings are developer-shaped). The composition reuses `LoadErrorRetry` extended with an optional `message` prop (default stays `LOAD_ERROR_COPY`, so the dashboard is untouched — one implementation, two messages).
