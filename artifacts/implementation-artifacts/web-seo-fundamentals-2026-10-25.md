# Story: fenzit-web SEO fundamentals — 2026-10-25

Direct user request: "improve the SEO of the fenzit-web project — research the internet and the
project, check what can be improved, and make the changes." BMAD flow run with three parallel
research agents (project audit, 2026 best-practice research against Google Search Central /
web.dev / Cloudflare docs, live-site probe of fenzit.com), then a single implementation pass in
`workspace/core/frontend/fenzit-web`.

## Findings (research, 2026-10-25)

Solid already: prerendered crawlable HTML for `/` and `/features` (56 KB of content in the raw
HTML), one h1 per page, complete OG/Twitter/JSON-LD set on `/`, `lang="en"`, http→https 301,
real 404 status via `not_found_handling: "404-page"`, self-hosted preloaded WOFF2.

Gaps, in priority order:

1. **`/features` ships the home page's head verbatim** — `scripts/prerender.ts` replaces only
   `<div id="root">`, so `/features` carries the home title/description and
   `canonical: https://fenzit.com/` + `og:url https://fenzit.com/`: it declares itself a
   canonical duplicate of `/`. No per-route head mechanism exists.
2. **`https://fenzit.com/og-image.png` is a live 404** — referenced by og:image, twitter:image
   and JSON-LD Organization.logo (already standards §12.8).
3. **No sitemap.xml; robots.txt is only the Cloudflare content-signals comment block** — no
   `Sitemap:` line, no rules.
4. **`/login` and `/admin` are indexable** — the client-only shells ship `robots: index, follow`
   plus the home title/description/canonical.
5. **`www.fenzit.com` has no DNS record** (unreachable, not redirecting) — infra, outside the repo.
6. Minor: dead `meta keywords` tag (Google: "no effect at all"), favicon links point at the hashed
   Vite asset instead of a stable URL, JSON-LD logo points at the missing 1200×630 og-image (Google
   wants a square ≥112×112), no `site.webmanifest`, `/features` has no client-side `<title>`, the
   hero mockup panels emit two decorative `<h2>`s into the heading outline, standards §3/§12 docs
   drift.

Research corrections vs older advice (sources in the session log): FAQ rich results were fully
removed from Google in May 2026 → **do not add FAQPage markup**; SearchAction/sitelinks search box
deprecated (2024) → keep it out; meta keywords confirmed zero-effect → remove; full `twitter:*`
stacks are redundant (X falls back to OG) → `twitter:card` + OG is enough; hreflang not needed for
a single-language site; lastmod is trusted only when verifiably accurate → omit rather than guess;
`html_handling: "drop-trailing-slash"` matches react-router's no-slash links.

## Decisions

- **Layer**: all FE (`fenzit-web`) — the site is static; nothing for `fenzit-be`.
- Per-route head is **baked by the prerender script** (regex-swap title/description/robots/
  canonical/og:url and, for indexable pages, og:title/og:description/twitter:title/
  twitter:description), throwing if a tag goes missing so template drift fails the build. Home
  keeps its hand-written head in index.html (it is the template); `/features` gets its own meta
  from a shared `src/app/pageMeta.ts`; client-only shells and 404 get `noindex`, their own title
  and no canonical.
- **Titles/copy**: home title/description/OG copy stays exactly as the user wrote it, including
  "| Coming Soon" (marketing call — flagged, not changed). `/features` gets a new title +
  description in the same voice. *(Amended same day: the user confirmed the site is live, so the
  "| Coming Soon" suffix came off the home title; "Launching 2026." remains in the three
  description tags pending the user's wording call.)*
- **Noindex by meta, never robots.txt-blocking** login/admin (page must stay crawlable for the
  noindex to be seen).
- **Sitemap** generated by the prerender script from the indexable page list (no lastmod —
  nothing verifiable dates it), robots.txt gains the `Sitemap:` line and loses the inert
  boilerplate.
- **og-image.png** (1200×630) generated with `sips` from the brand glyph on the page surface
  colour `#F9FAFB` — no new dependencies (exact-pin + two-week rule). `public/logo.png` (copy of
  logo-3x) becomes the stable favicon/apple-touch-icon/JSON-LD logo URL.
- **wrangler** gains `html_handling: "drop-trailing-slash"` so `/features` (the form every
  internal link uses) is canonical and `/features/` 307s to it.
- Hero mockup `<h2>`s become `<p>` (class styling unchanged) so the outline reads h1 → section h2s.
- Deferred, with reasons: FAQPage/SoftwareApplication `offers` (no rich result possible
  pre-launch/ratings), BreadcrumbList (single-level nav), security headers/CSP (standards §11
  owns that), www→apex redirect (needs Cloudflare DNS + redirect rule, dashboard-side), GSC/Bing
  verification and sitemap submission (user accounts; steps written into the README).
