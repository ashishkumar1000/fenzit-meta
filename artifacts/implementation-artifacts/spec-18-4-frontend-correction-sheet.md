## 2. Design decisions

**D1 — Entry + gating (pre-empting the wire's reachable 422s).** The DayDetailSheet (owner scope ONLY) gains one entry — a secondary full-width **"Correct day"** button — rendering only when BOTH hold: `workDate ≤ today` (both are zero-padded `YYYY-MM-DD` tenant-local strings from the same wire vocabulary; lexicographic compare is valid, and today only moves forward, so the FE can allow something the BE later rejects as future — but never the reverse) and `day.status !== 'not_tracked'` (the BE's DATE_NOT_TRACKED gate is the SAME engine output the row renders — the rule-1 history-preservation arm cuts the same way both sides). The gate is **data-driven and refetch-fresh only** (state lens #5): hosts refresh on app foreground (AppState → the D6 refresh) and after save; a day aging into correctability appears on the next fetch — never from the device clock. A `me`-scope sheet NEVER renders the entry (FR-21: only the owner corrects). The **lab's proof month suppresses the entry entirely** (canned data + a placeholder UUID would 404 no-leak — a baffling error on fake data): the proof-pane sheet passes the read-only posture.

**D2 — The correction STAGE (a morph inside the Day Detail — never a stacked second sheet).** The repo's settled doctrine (17-7 D1; the LeaveDetailSheet/RevokeSheet headers carry it in prose; stacked TrueSheets are an untested native edge whose Android-back ordering during the present animation dismisses the UNDERNEATH sheet) and the mock agree: **Frame B is ONE sheet whose content swaps under the SAME day heading.** DayDetailSheet gains `stage: 'detail' | 'correct'`: "Correct day" sets the stage; the title stays "{Weekday}, {d} {Month}" and the subtitle stays the day's current times line (the mock's sub-slot); the content swaps to the correction form, which **mounts fresh on every stage entry** (17-7's stage-state-reset idiom) with a **Back** ghost button returning to the detail stage (disabled mid-write). Form anatomy, top to bottom: the day's flag badges (repeated from the detail stage, the mock's flagbadge row) → the mode `SegmentedControl` (**"Times"** / **"Status"** — the XOR arms as UI) → the mode's fields → the note → the InlineError slot → **"Save correction"**. **Times mode:** "Check-in time" (REQUIRED) + "Check-out time (optional)" — the office-form field anatomy VERBATIM (`Input`, placeholder "09:00" or the pre-filled wall time, `maxLength={5}`, `keyboardType="numbers-and-punctuation"`, trailing Clock adornment; the 24-hour guidance lives in the error copy "Use 24-hour time, e.g. 09:00"/"…18:00", shown onBlur — no invented helper hint). **Status mode:** the mock's "Set day status" label above a three-way segmented pick (Present / Half day / Absent — the only wire statuses). **Pre-fill at stage entry from the host's CURRENT row** (the same live row the detail stage renders — a mid-open refetch is picked up because entry derives at tap time): existing instants fill the time fields (their wall-clock parts, AD-7 verbatim), an existing times-override opens in Times mode, a status override in Status mode with that status; the default for a day with no times is Status. **State ownership:** all form state (mode, check-in, check-out, status, note, error) resets on every entry and never survives close (Sheet content stays mounted — the reset kills cross-day leaks); per-field values are LIFTED ABOVE the mode switch so entered values survive mode flips (Times prefilled → Status → Times keeps them); the XOR body builds from the ACTIVE mode's fields only. **Submit-time validation into the fields' error slots** (office copy): Save correction stays disabled until the trimmed note has ≥ 1 character AND, in Times mode, check-in is a valid `HH:mm` and check-out, when filled, is valid — and if check-out is filled while check-in is invalid/cleared, submit blocks with the check-out field's error "Enter a check-in time first" (the field keeps its text; never disabled mid-edit) — making the wire's checkout-alone and INVALID_RANGE 422s unreachable except the server-side instants-after-now edge, which surfaces verbatim. **Instant construction:** submit builds `${workDate}T${HH:mm}:00${offset}` where `offset` = `tenantOffsetFromCarried(...)` — the first non-null carried instant's `slice(-6)` across the day/month rows, falling back to the documented IST `'+05:30'` constant (the 17-7 non-IST caveat, already in deferred-work). The sheet stays **content-sized** (`detents={['auto']}`, no footer).

**D3 — The note gate (epic AC 2).** Label **"Note (required)"** (the mock's label; the app's "(required)"-suffix idiom), placeholder **"What was wrong?"** (the RevokeSheet question-as-placeholder idiom), multiline, maxLength 500, `accessibilityLabel="Note (required)"` — counter below the field, right-aligned "{n} / 500", amber from 450 (the RevokeSheet counter verbatim). The primary `Button` labelled **"Save correction"** (epic AC 2's exact label; `variant="primary"` — a correction CREATES an audit entry, it destroys nothing) stays DISABLED until the D2 gates pass — the gate carries `accessibilityState`, no error-shaming banner, and makes the wire's note-hygiene 422 unreachable except deliberate control chars.

**D4 — Submit + failure postures.** Save sends the XOR body (NO idempotency key — a replay is a re-correction, which is exactly why the press handler **latches in a ref** (the `useWeeklyOffDefaultForm` submitLatchRef pattern — `loading` is async state and a same-tick double-tap would file TWO audit rows); one release in `finally`; Back disabled mid-write). While in flight the sheet flips `dismissible={false}` (ONE sheet — the 17-7 WRITE posture is now unambiguous), the button spins. **Offline:** a NetInfo probe at press (`isOfflineNow` idiom — a failing probe assumes online and lets the POST fail); offline → InlineError "You're offline. Correcting attendance needs a working connection.", sheet open, entries intact. Failure → InlineError with the SERVER message verbatim, rendered between the note and Save correction; a non-server (network) failure renders "Couldn't save the correction. Check your connection." — the entries, mode and note all survive.

**D5 — Success = stale-while-revalidate in-place refresh (epic AC 3, the UJ-4 climax).** On `200 {workDate, override, correctedAt, actorId}` the stage morphs back to detail (the row changed — 17-7's morph-back idiom) and the HOST calls the hook's **`refresh()`** — a DISTINCT stale-while-revalidate path, NOT the clearing month-change fetch: **existing rows are kept** (no `setData(new Map())` — the clearing path would blank every cell to Not-tracked and flip the open sheet's row to a false "Not tracked" mid-flight, the exact misrepresentation the fail-closed rule forbids), no month-level spinner, seq-guarded, rows swap when the fetch lands. The pinned interim: the OLD glyph retained until the swap — the cell updates **in place, without reopening, as soon as the refetch lands, and never blanks or flips to Not tracked mid-refresh** (optimistic seeding from the 200 is NOT honestly available: the response carries the RAW override, not the recomputed row — the FR-10 engine owns the displayed status, one implementation). The detail stage then follows the live row: the badge flips, the "Corrected" flag appears, the quoted note renders; the correction HISTORY refreshes on the stage's next entry (the quoted note/flag are live via the row — the expanded list is not re-fetched mid-stage). The AC's "any open summary totals" clause binds the 19-5 host through this same `refresh()` contract; 18-4 witnesses the cell + the lab.

**D6 — Service + hook surface.** `attendanceCorrections.ts` grows `correctDay(employeeId, workDate, body)` + the XOR body type + the result type `{workDate, override, correctedAt, actorId}`, and the header error map gains the write 422 subcodes (`ATTENDANCE_FUTURE_DATE`, `ATTENDANCE_DATE_NOT_TRACKED`, `ATTENDANCE_INVALID_RANGE`, `VALIDATION_ERROR`) beside the read codes. `useMonthStatuses` gains `refresh()` (the non-clearing path; `retry()` keeps its error-recovery semantics).
