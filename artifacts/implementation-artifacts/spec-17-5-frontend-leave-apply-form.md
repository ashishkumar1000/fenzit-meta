## 2. Design decisions (locked before implementation)

**D1 — Entry point: a pushed full-screen `LeaveApply` route on the TECHNICIAN root stack, from the Attendance tab in `active` AND `upcoming`.** The tab's summary area gains a "Leave" section (SectionHead "Leave") with an "Apply for leave" row; 17-6 grows history under it. Both states render it (BE gate 17-4 D9: upcoming can apply, date-floored server-side); `history_only`/`none` never do (D9 gate 403s; FR-15 read-only posture). Renders regardless of location-permission state (FR-4). Route params: `{ today: string | null; pickedDate?: string | null; context?: 'from' | 'to' | null }` — `today` is the server-provided date from the tab's loaded summary (active) or null (upcoming — the wire has no today outside active, attendanceMe.ts `today` active-only); `pickedDate`/`context` are the DatePickerScreen return channel, consumed **read-once-then-cleared** (`setParams` null-out, the 15-9 RosterScreen idiom) so a stale pick can never re-fire. **Access-flip safety:** the hook observes the access store; a flip to `none`/`history_only` while this screen is on top (mid-session owner disable — the tab's own guard only fires when the tab is focused) pops back to the tab immediately (a submitted write stands, idempotent; the form is disposable). On `ATTENDANCE_NOT_TRACKED` from either endpoint: render the server message + force `refreshAttendanceAccessNow()` (the store flip then drives the pop-back).

**D2 — Screen composition (mockup Frame A anatomy; DS components verbatim; zero new shells/colours).**
Header "Apply for leave" (`ScreenHeader`, the attendance/offices precedent) → scrollable content (`surfacePage` bg, `spacing.s4` padding/gap) → **pinned footer** (DatePickerScreen's pinned-confirm idiom: `surfaceCard` bg, hairline top border `borderSubtle`, `spacing.s4` padding) containing the D6 inline-error slot (`InlineError`) above the submit `Button` (primary, size lg 52, fullWidth, "Submit for approval", `loading` during the POST — never a disabled swap). Content order:
1. **Type** — bare `Eyebrow` "Type" (first block, divider-less form), then `SegmentedControl` with options Full day / First half / Second half (`full_day | first_half | second_half`). With a range picked the control renders a **single "Full day" segment** (D3) — the block never hides (hiding would orphan the reset note and cause a jarring reflow).
2. **Dates** — `SectionHead` "Dates", then two **stacked full-width tappable rows** (From, To), visually cloned from `DatePickerField`'s row anatomy (label, 48px `touch.comfort` value row, 1px `borderDefault`, `radius.md`, trailing `CalendarDays` icon 20/stroke 2/`textMuted`; rows gap `spacing.s3`). `DatePickerField` itself is an **inline-calendar** component (its press toggles the DS `Calendar` in place) — the ROW STYLE is cloned, the component is never imported; each row's press navigates to the full-screen `DatePickerScreen` (Material's narrow-viewport guidance and the deferred-work adoption directive both point here). `To`'s placeholder reads "Optional"; `To` is tappable only after `From` exists. Value text `typography.body`/`textStrong` via `formatLongDate` (regex-guarded; non-ISO passes through — there is no `.slice` in the util, that lives in the picker's `toIso`).
3. **Count** — the hero feedback, directly under the To row inside Dates (`marginTop: spacing.s3`): a self-starting pill — `colors.primarySoft` bg, 1px `colors.status.progress.border`, `radius.pill`, `CalendarDays` 16/stroke 2/`colors.status.progress.fg`, text `typography.bodyStrong`/`colors.status.progress.fg`, padding s1×s3, gap s1, `accessibilityLiveRegion="polite"`. In-flight: `opacity: 0.6` dim of the previous value (no spinner swap, no layout shift). No count yet (no From): a muted `bodySm`/`textMuted` line at the same position — "Pick dates to see the working-days count." — so the rhythm holds.
4. **Reason** — `SectionHead` "Reason (required)", then `Input` multiline `maxLength={500}`, **no `required` prop** (the section head carries the name; passing both double-marks the field), `accessibilityLabel="Reason (required)"`, placeholder "Why do you need leave?". Counter: right-aligned `caption`/`textMuted` "{n} / 500" below the field (`marginTop: spacing.s1`), flipping to `colors.status.scheduled.fg` at n ≥ 450.
Footer sits inside the SafeArea bottom edge; `KeyboardAvoidingView` per the AddCustomerScreen form precedent (there is no shared Screen component). The DateTimeFields→DatePickerScreen swap vs the epic AC's literal wording is a **documented deviation**: NFR-12 bans importing `features/newJob`, and deferred-work.md directs adopting `AttendanceEnrolments/DatePickerScreen` at every remaining date-input site ("do NOT fork a second picker implementation"). File ≤ 300 lines.

**D3 — Single-date rule (pure model `leaveApplyModel.ts`).** `isSingleDate = to == null || to === from` (wire-shape truth). **Half-day options visible only when `from != null && isSingleDate`** (EXPERIENCE: "only appear once exactly one date is selected" — zero dates ⇒ three... no: zero dates ⇒ Full-day only; the empty state never shows half-day options). Range picked ⇒ the control shows the single "Full day" segment (D2). **Reset rule:** a second (different) date picked while `part ≠ 'full_day'` ⇒ part resets to `full_day` + the note "Leave type reset to Full day — half day applies to a single date only." renders **under the Type control** as `InlineNotice` tone neutral (`accessibilityRole="alert"`); the note clears on the next type or date change. **Clear affordance:** when `To` is filled, the To row carries a small "Clear" pressable (right of the date, ≥44px target): clears `To` → half-day options return; `part` stays `full_day` (no silent restore of a previous choice — the user re-picks explicitly). From moved past a picked `To` ⇒ `To` clears (never an inverted range on the wire). **Wire normalization:** `isSingleDate` ⇒ `endDate` omitted (never a same-day duplicate; `To == From` normalizes to single-date and half-day stays allowed — the BE treats start==end as single-date); `part` sent only when `≠ 'full_day'` and single-date (BE defaults `full_day` on the DTO — verified). Form invariant: `To` can never exist before `From` (row disabled until From).

**D4 — Live preview: latest-wins GET, only when `From` is set.** `GET /attendance/me/leave/preview?startDate&endDate?&part?` fires on every (from, to, part) change **only when `from != null`** (no From ⇒ no GET — the BE requires startDate, and a part-only query would 422 as a fake "connection error"). **Race latch: a monotonic request sequence number, not a param key** — a From→B→From-A-again triple-key would let a stale response answer the newest request; only the newest seq renders, and a response landing after unmount is dropped. `ok: true` ⇒ the count chip renders the server's `workingDays` **verbatim — an integer** (the BE counts dates: `countWorkingDays` = filtered length; a half-day single date renders "1 working days"-class copy via the model's plural rule, the half-ness is conveyed by `part` on the Type control, NOT a 0.5 count — the earlier 0.5 pin was a wire fiction, removed). `ok: false` ⇒ the chip is replaced by `InlineNotice` tone **info** (amber — information, not failure; the holidays-banner precedent) with the server message verbatim; the `errorCode` union is the FULL rejection set `{ATTENDANCE_NOT_TRACKED, LEAVE_INVALID_RANGE, LEAVE_BEFORE_START_DATE, LEAVE_TOO_OLD, LEAVE_CHECKED_IN_CONFLICT, LEAVE_ALREADY_OFF, LEAVE_OVERLAP}` — the preview gate answers gate failures (incl. NOT_TRACKED) and overlap as `200 {ok:false}`, NOT as HTTP errors (the 17-4 "preview 403" review patch never landed; verified at leave-read.service.ts). `ATTENDANCE_NOT_TRACKED` additionally forces the access-store refresh (D1). Transport failure ⇒ `InlineNotice` tone **neutral** "Couldn't update the working-days count. Check your connection."; submit stays enabled in every case (the AC's never-pre-disable rule covers the five range rejections; the POST re-renders the authoritative message anyway). No debounce: changes are discrete taps, one GET per change.

**D5 — Submit: required-field gate, fresh key per tap, announce-and-leave.** The button is disabled until **`from != null && reason.trim() ≠ ''`** (the house required-field pattern — Correction sheet precedent; NOT one of the AC's five rejections, which stay never-pre-disabled: with dates + reason filled, the button is always enabled and rejections fire inline on tap). On tap: `submitting` latch (double-tap no-op), button `loading`, `POST /attendance/me/leave` body `{startDate, endDate?, part, reason}` + `X-Idempotency-Key = generateIdempotencyKey()` at tap time. **201 = success — create AND replay are the same handler/status** (`@HttpCode(CREATED)`; the replay returns the stored view, no second shape) ⇒ `AccessibilityInfo.announceForAccessibility("Leave request submitted")` → `goBack()` to the tab (history surfaces it in 17-6; no success screen). Unmount mid-flight is safe (hook guards; the idempotent write stands).

**D6 — Error posture: the server's message, inline, every time (16-4 D10 posture).** POST `ApiError` ⇒ `InlineError` (red, non-dismissible) in the footer above the button, `ApiError.message` verbatim. Wire codes the hook recognises: `LEAVE_INVALID_RANGE | LEAVE_TOO_OLD | LEAVE_BEFORE_START_DATE | LEAVE_ALREADY_OFF | LEAVE_CHECKED_IN_CONFLICT` (422), `LEAVE_OVERLAP` (409) — **shipped strings after `3684775`**: "These days are already off" / "You can only apply for leave up to 7 days in the past" / "You can only apply for leave from {startDate} onward" / "You already checked in on {date}, so it can't be requested as leave" / "You already have a leave request covering one of these dates"; `LEAVE_CHECKED_IN_CONFLICT` has a second live variant from the 18-2 corrections mirror ("You have a correction on {date}. It cannot be requested as leave") — same handling (verbatim render; the code is what the FE branches on, never the string). `ATTENDANCE_NOT_TRACKED` (403 on writes) ⇒ message + `refreshAttendanceAccessNow()` (D1 pop-back follows). `DUPLICATE_RESOURCE` ⇒ server message (raced key across employees; not a recovery path). `VALIDATION_ERROR` ⇒ server message (DTO trim/empty/span). `NETWORK_ERROR | TIMEOUT` ⇒ "You're offline. Submitting leave needs a working connection." Anything else ⇒ `ApiError.message`, falling back to a generic line when empty. The message area clears on the next param change; every settled failure announces its message. **Reading order of co-visible inline texts (a11y + visual):** Type block (control → reset note) → Dates (rows → count chip / preview notice) → Reason (input → counter) → footer (error → button) — the DOM/a11y order IS the visual order; no absolute-positioned overlays.

**D7 — Service: `services/resources/attendanceLeave.ts`** (plain apiClient functions, the attendanceCheckIn.ts shape): `previewLeave(params)` → `{ ok: true; workingDays: number; totalDays: number; part: string; dates: { date: string; isWorkingDay: boolean; kind: string }[] } | { ok: false; errorCode: <D4 union>; message: string }`; `applyLeave(body, idempotencyKey)` → `LeaveRequestView { id, employeeId, startDate, endDate, part, reason, status, workingDays, totalDays, createdBy, createdAt, dates: [{ date, state }] }` — **`totalDays` is on every view incl. POST 201** (verified at `toRequestView`; the 17-4 contract doc omitted it; `employeeName` is list-only, never here). Dates stay strings (AD-7 — never `new Date()`). Export via the resources barrel (`src/services/resources/index.ts`).
