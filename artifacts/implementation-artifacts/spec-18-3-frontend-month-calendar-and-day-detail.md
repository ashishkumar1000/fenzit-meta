- **Story:** 18-3 — the SHARED layer of the month views: the 12-status visual system, the `MonthCalendar` grid, and the `DayDetailSheet`. Epic 19's host screens (19-5 owner monthly view, 19-6 self-view) embed these as-is — "built in Epic 18 … no second calendar implementation" (epic §19.5).
- **Repos:** fenzo-app + ONE small additive BE change shipped first (the 16-4/17-8-D1 precedent: UX-mandated sheet fields no shipped read carries).

## 1. Fix-placement analysis (incl. the additive BE change)

The Day Detail sheet's FR-25 field list promises **distance from the office pin at check-in/check-out**. The write path already computes and STORES it (`attendance_records.checkin_distance_m` NOT NULL / `checkout_distance_m` nullable, set by the 17-4 gate) — but the day-statuses READ drops both columns.

| Concern | Layer | Why |
|---|---|---|
| `DayStatusRow` += `checkinDistanceM` / `checkoutDistanceM` (number \| null) **and** both day-statuses envelopes += `today: string` | **BE** (additive read fields) | The sheet field is wire-owned; the distances already exist at rest. **Distance is emitted ONLY when the paired source is `'gps'`** — a times-only correction substitutes manual instants while the stored distance still describes the ORIGINAL GPS fix; pairing them would misstate the fact (wire lens #2), so the wire field means "the GPS-measured distance of the recorded instant", null for manual or no-record. `today` is already computed internally per read (`day-status.read.ts` `DayGridRow.today`) but never echoed — hosts and the today ring need the tenant-local date WITHOUT doing their own timezone maths (Foundation rule; state lens #1). No computation, no schema change. |
| 8 new `colors.status` keys + the status→{colour, icon, label} table | **FE** | Presentation vocabulary (UX-DR1); `Badge` already renders `colors.status[key]` + an `icon` slot — keys are additive, job statuses untouched, job rendering byte-identical. `in_progress` maps to the EXISTING `progress` key (the DS's own "don't invent synonyms" rule — wire lens #12). |
| `MonthCalendar`, `DayDetailSheet`, `useMonthStatuses`, dayStatuses/corrections services, correction-history read | **FE** | Pure presentation over shipped reads (owner + me day-statuses; owner + me corrections). |
| Client month-span construction (≤ 31 days, under the wire's 62 cap) | **FE** | BE 422s `ATTENDANCE_INVALID_RANGE` regardless (NFR-2); the FE never builds an over-cap request. |
| Correction WRITES, acknowledge-fake-location action | not here | 18-4 (writes); the acknowledge action has no owning story yet — recorded in §4. |

**Shipping order:** BE fields land → commit/push (auto-deploy) → FE consumes. FE tolerates absence defensively (legacy read ⇒ null/absent ⇒ the distance line and today-fed ring degrade honestly).

## 2. Design decisions

**D1 — The status visual system (UX-DR1), one table, three consumers.** `theme/colors.ts` gains **8** additive keys mapped to the EXISTING 5 hue families (values reused, no new palette entries): `leave` + `halfDayLeave` (planned/blue), `weeklyOff` + `holiday` + `notTracked` + `notCheckedIn` (neutral/gray), `workedHoliday` (worked/green), `checkoutMissing` (partial/amber); `in_progress` renders on the existing `progress` key. A new pure model `dayStatusVisual.ts` is THE single table: wire `status` (all 12 `DayStatusKey`s — verified the closed BE enum) → `{ badgeStatus: StatusKey, icon: LucideIcon, label }` — icons exactly per the DESIGN.md table (CheckCircle2, Clock, XCircle, CalendarOff, CalendarClock, Moon, Flag, Briefcase, AlertCircle, MinusCircle, Circle, Play — all present in lucide-react-native 1.48), labels verbatim. `tone="soft"` everywhere in this module. Flag tags (Late · {n}m / Early · {n}m / Fake location / Leave pending / Corrected) derive from `markers` (typed as the closed marker union, NOT `string[]`) + the late/early minutes via a sibling `dayFlagVisuals(day)` helper — Badge `size="sm"`, DESIGN.md icons. **The 12px same-hue distinctness proof (epic AC 1) is a shipped dev artifact, not a claim:** the ComponentLab's throwaway month (D7) renders all 12 at real cell size; the walkthrough screenshots record every same-hue pair (amber: Half day `Clock` vs Checkout missing `AlertCircle`; blue: Leave / Half-day leave / In progress; gray: the four neutral icons; green: Present vs Worked on holiday). The automated distinct-names test is coverage only — the screenshot is the proof (the Floor explicitly rejects token-table-only evidence).

**D2 — BE additive (SHIPS FIRST): two distance fields + the `today` echo.** Both day-statuses responses (owner + me) gain `today: string` (tenant-local, the same internally-computed value the engine uses) and every `DayStatusRow` gains `checkinDistanceM` / `checkoutDistanceM` (number | null; check-in is NOT NULL at rest so it is null only when no record row exists; check-out is genuinely nullable; **either is null when that instant's source is not `'gps'`**). Controller swagger + `docs/api-contracts.md` update + one real-DB probe (a gps day, a manual-corrected day, a no-record day). Nothing else on the wire changes.

**D3 — `services/resources/attendanceDayStatus.ts` + the `useMonthStatuses` hook.** `fetchDayStatuses(employeeId, from, to)` `[owner]` and `fetchMyDayStatuses(from, to)` `[technician]`; `DayStatusRow` type byte-parity with the contract (21 fields + the new three; `markers: DayMarker[]` closed union; `latestCorrection?` — ABSENT on uncorrected days, and the normalizer keys off that absence, never off a null); a strict whitelist normalizer that is **fail-closed at the FETCH level: one unknown status word fails the whole fetch** (a month minus one silently-Not-tracked row is the exact misrepresentation this forbids — state lens #12). The me paths' `403 ATTENDANCE_NOT_TRACKED` maps to the ordinary error state (the access UI is 19-6's concern). `monthRange('YYYY-MM')` → `{ from, to }` (calendar bounds; structurally under the 62 cap, which 422s `ATTENDANCE_INVALID_RANGE` on both endpoints). AD-7: instants render as carried — never converted. **`useMonthStatuses({ scope, employeeId?, yearMonth })` owns the lifecycle** (state lens #2/#5): fresh fetch on mount AND on every month change (no cache — the 17-6 param-landing precedent; an 18-4 correction must appear on the next visit), a **last-request-wins sequence guard** (fast ‹ › paging: the latest request's resolve wins, stale resolves dropped), month-level loading (the established centred spinner — see D5's Skeleton note), and `InlineError` + Retry on failure. Midnight-crossing staleness of today's cell is accepted until the next fetch (documented; the ring is data-driven from `today`, never the device clock).

**D4 — `MonthCalendar` (pure, host-fed).** Props: `{ yearMonth: 'YYYY-MM', days: ReadonlyMap<string, DayStatusRow>, today: string, onPickDate: (workDate: string) => void }` — `today` comes from the D2 echo, never the device clock. **Sunday-first** 7-column grid (RESOLVED per the mock's `S M T W T F S` header — and a recorded trap: the weekly-off picker cited for the letter pattern is MONDAY-first in code, `WeeklyOffDayPicker.tsx` — reuse its letters + full-a11y-names pattern, never its ordering); weekday header single letters `fontSize['2xs']` semibold `textMuted`; leading blanks for the 1st; 5–6 rows. Cell: a square soft chip (`aspectRatio: 1`, `radius.sm`) — background `colors.status[key].bg`, date number (`fontSize['2xs']` bold, above) and ONE 12px icon glyph in `colors.status[key].fg`, the identical mapping Badge `tone="soft"` uses; **no text label in the cell**; number and glyph are fixed-size (no Dynamic Type scaling — the sheet's full label is the accessibility fallback). A day with no row or `not_tracked` renders the neutral `MinusCircle` glyph — never blank. Today's cell: a `colors.primary` outline ring at `borderWidth: 1.5` (the app's established today treatment in `ui/Calendar.tsx`) regardless of glyph; **no status carries a ring of its own** (the mock's inset rings on checkout-missing/worked-on-holiday are mock-only noise — a blue inset ring would be indistinguishable from today's). The WHOLE cell is the tap target (the Accessibility Floor's stated ~40px exception, scoped to calendar cells) → `onPickDate(workDate)` for ANY date including future ones. Cells memo on their row; hosts pass a stable `onPickDate` (state lens #14). Accessibility: `accessibilityLabel` = "{day} {Month}, {label}" — and "{day} {Month}, today, {label}" for today (the ring must not be visual-only) — `accessibilityRole="button"`. No summary chips, no legend, no month navigation inside the component (host furniture, §4).

**D5 — `DayDetailSheet`.** The app's native `Sheet` (whose `title` is a REQUIRED prop), titled **"{Weekday}, {d} {Month}"** (e.g. "Monday, 14 September" — the mock's sheet heading); NO subtitle (the mock's muted times line would duplicate the rows). The sheet is presentational: `{ visible, workDate, day: DayStatusRow | null, … }` — it renders the host's CURRENT row, never a mount-time snapshot (today can change under an open sheet; hosts refetch and the sheet follows). Content, top to bottom: the full `StatusBadge` (icon + label, soft — visually primary, first block); the flag-tag row — a WRAPPING row (`flexWrap: 'wrap'`; Badge truncates by default and a clipped "Fake location" tag is a trust failure on the audit surface); labelled value-rows in the module's muted-label/strong-value anatomy (the DoneCard pattern): Check-in ("10:22 AM" via `formatOffsetInstantTime`; when the gps distance exists, " · 42 m from {officeName}"; " · At the office" only when the distance is 0 m — the FE never guesses the geofence radius; a checkout whose carried date ≠ workDate appends "(next day)"), Check-out likewise, Worked hours (via `formatOffsetInstantDate`/`formatWorkedMinutes` — "8 h 08 m"), Office name. **Omission rule: a line with no value does not render** — a no-row day opens as "Not tracked" (status badge only); a future date shows only its known state (weekly off / holiday / leave) with no time rows; the corrections section renders only when ≥ 1 correction exists. **Corrections:** the latest correction's note as a quoted line; when the date carries MORE than one correction, an expandable **"Correction history · {n} corrections"** row-card (row-card tokens, trailing `ChevronRight` → `ChevronDown` when expanded — the EnrolmentRowActions disclosure pattern; `accessibilityState={{ expanded }}`, count = the loaded page's count), expanding to a scrollable list (fixed detent + scrollable content — 50 entries must stay reachable) of EVERY entry: actor + when (caption, muted; a null actor renders "Owner"), "{old} → {new}" (values through the D6 formatter), the note quoted. History source: `GET /attendance/corrections?employeeId&workDate` `[owner]` / `GET /attendance/me/corrections?workDate` `[technician]`, first page `limit=50`; a returned `nextCursor` renders "Show earlier". **Fetch hygiene (state lens #3):** history fetches are keyed by `workDate`; a resolve for a non-current day or after dismissal is DISCARDED (Sheet content stays mounted while closed — an unkeyed fetch would paint day B with day A's history); per-open UI state (expanded, error, loading) resets on every open; the sheet stays dismissible during reads (the `dismissible={false}` flip is a WRITE posture, 17-7 precedent). Loading = the sheet's established small-spinner posture (`ActivityIndicator` in `colors.primary`); failure = `InlineError` + Retry. The sheet announces on present (`AccessibilityInfo.announceForAccessibility("Day detail, {d} {Month}")` — the OwnerLeaveScreen idiom) and is strictly read-only (18-4 owns writes).

**D6 — `services/resources/attendanceCorrections.ts`.** `fetchCorrections({ employeeId? | me, workDate?, cursor?, limit? })` returning the house **`Paginated<CorrectionEntry>`** (`{ data, nextCursor, hasMore }` — `src/services/api/pagination.ts`, the exact reuse `attendanceLeave.ts` already makes) with `CorrectionEntry` byte-parity (`{ id, employeeId, workDate, correctedAt, actorName: string | null, note, oldValue, newValue }` — `oldValue`/`newValue` are nested `{ status, checkinAt, checkoutAt }` where status may be ANY of the 12 keys and instants are tenant-offset ISO). One small formatter renders a value: a status word → its D1 label; with instants → "Times 9:02 AM – 6:00 PM"; empty → "—". Error mapping documented on the service like the sibling resources: missing/malformed `employeeId` → 422; a foreign-scope or malformed cursor → **400** `VALIDATION_ERROR 'Invalid cursor'` (a deliberate non-house 400 — pinned so the FE maps it, not the 422 handler); `me` with access none → 403 (ordinary error state). Cursor scopes `day-corrections-owner` / `day-corrections-me` are never interchanged.

**D7 — `__DEV__` ComponentLab (the story's walkthrough host + the AC-1 proof).** A dev-only route: the `require()` sits INSIDE the `if (__DEV__)` branch of RootNavigator (+ route types) so the module is behaviourally absent from release bundles — Metro DCE kills execution, not module bytes, so the release proof is a bundle grep for a lab marker string (mirroring `scripts/verify-metro-debug-bundle.js`), pinned as a build step. Entry: a dev-only row at the bottom of the owner Attendance home ("Component lab (dev)"). Content: (a) the **throwaway proof month** — canned rows GENERATED by mapping an exhaustive 12-key list through `dayStatusVisual` (never hand-written colours/icons — a table drift then breaks the lab, not silently mis-renders); (b) a **real month** — employee picker (id→name from the MMKV-hydrated `ProfileTechnician` roster store; the day-statuses wire never carries employeeName) + month nav ‹ › through `useMonthStatuses`, whose cells open the REAL `DayDetailSheet` against production data. Clearly-labelled lab scaffolding; 19-5/19-6 replace it as the real hosts and the lab retires with them.
