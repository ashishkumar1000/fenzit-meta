## 2. Design decisions

**D0 — Sequencing.** 17-6 starts from the committed 17-5 tree. No file that 17-5 creates is edited blind: this story's build reads the landed code, never the spec alone.

**D1 — Owner surface: "Leave" tile → `OwnerLeaveScreen` with a `SegmentedControl` Pending | All switch (settled: segmented, not tabs — one surface, one filter param; the OfficesScreen idiom; no badge counts — the wire has no total and a red badge over-alarms).** AttendanceHome gains the Leave `Tile` ABOVE Offices (`CalendarOff`, `colors.status.progress` family — Leave is "planned time"; subtitle "Pending requests & history" is FE copy, not mockup text). Screen: `ScreenHeader` "Leave"; full-width "Apply on behalf" primary CTA card at the top (OfficesScreen "Add new office" pattern: `colors.primary` bg, `radius.lg`, icon tile `Users` — settled Q3; visible on both tabs; a header link is a weak affordance and an EmptyState CTA vanishes when the queue fills). List: FlatList of request rows, pull-to-refresh (announce "Leave requests updated"), `EmptyState`s per tab (Pending: "No pending requests" / "You're all caught up. New leave requests will show up here."; All: "No leave requests yet" / "When your team applies for leave, it will show up here." — no CTA on either, the card above competes). First load: centred `ActivityIndicator` (no skeleton — unbuilt); load failure: `InlineError` + Retry; refresh failure with data: "Couldn't refresh. Showing the last loaded list."
**Per-tab pagination state (the v1 cursor claim was FALSE — cursors are endpoint-scoped, `leave-owner-list`, and a pending cursor CAN replay against the unfiltered list):** each tab keeps its own `{items, cursor, endReached, loading}`; `onEndReached` (threshold 0.4, JobsScreen footer-spinner idiom) paginates ONLY the active tab's cursor. **Switch semantics:** both caches persist; a tab re-entered after any write that could have touched it (or after foregrounding with a stale mark) refetches its first page. Pull-to-refresh resets the ACTIVE tab only. Writes invalidate BOTH tabs (D2).

**D2 — Request row → detail `Sheet` (`LeaveDetailSheet`), full action lifecycle.** Row: `Card` interactive (a11y label "Leave request for {name}, {dates}"), Avatar md, name `bodyStrong`, secondary line "{date range} · {n} working day(s)" (range helper: "14–18 Sep 2026", cross-year "28 Dec 2026 – 2 Jan 2027"; singular/plural shared with 17-5), **Pending-tab rows omit the status chip** (Frame B: every row pending; identical amber pills are noise); **All-tab rows carry it**. **Split requests (v1 gap — derived status is request-level while `dates[].state` mixes, live since 17-1..17-4's check-in auto-cancel):** the workingDays integer is span-wide and state-blind on the wire (verified) — so: row gains an honest suffix when `dates[]` has >1 distinct state ("· 2 of 5 days cancelled" / "revoked", majority non-active state); the sheet gains a per-day breakdown block (one line per date + small Badge from the chip table), split-only. The derived chip is never recomputed — the wire's truth.
Sheet (`detents=['auto']`, `dismissible={false}` while a write is in flight — ReassignOfficeSheet precedent): title = employee name, subtitle "Leave request" (the mockup's "Thane Office · office staff" line is UNRENDERABLE from `LeaveRequestView` — dropped, spines win); Avatar row; key–value rows Type / Dates / Working days / Status(chip); reason box (`surfacePage`, `borderSubtle`, typographic quotes); split block when split.
**Actions (Pending only), mockup order `[Reject] [Approve]` (primary rightmost):** Approve = `Button` primary lg, **single tap, no confirmation** (UJ-3). Reject = `secondary` lg + `labelColor: colors.danger`; pressing it swaps the action row for stage 2: optional `Input` (placeholder "Add a reason (optional)", maxLength 500, "{n} / 500" counter, ref-focused on mount), full-width `danger` "Reject request", ghost "Back" to stage 1. Empty reason valid.
**Lifecycle:** submitting latch (second tap no-op); pressed button `loading`; results: success ⇒ refreshed view drives the list update + `announceForAccessibility("Leave approved"/"Leave rejected")` + sheet closes; **`409 LEAVE_NOT_PENDING` ⇒ sheet content swaps to `InlineNotice` neutral "This request was already handled" + an "OK" button that closes — no auto-close timer** (a timed close flashes and races the announcement); the row refetches to true state; own-retry 200 ⇒ success path (one server event). **List update branches by tab: Pending ⇒ the row is REMOVED** (it's a filtered list — an approved row must not linger; the announcement + All tab carry the outcome); **All ⇒ replaced in place**. Both tabs marked stale.
**Terminal requests (Approved/Rejected/Cancelled/Revoked):** detail rows + chip only, no buttons, no revoke promise (17-7 owns it). Failure mid-write: sheet stays open, `InlineError` above the buttons, `ApiError.message` verbatim.

**D3 — Employee surface: "My leave" history under the Attendance tab's Leave section + tappable read-only detail (FR-17 v1 gap closed).** Compact rows below the apply row (no avatar): dates line `bodyStrong`, caption "{n} working days" + (" · First half"/"Second half" when part ≠ full_day), status `Badge` sm right. **Rows are tappable ⇒ the same `LeaveDetailSheet` in read-only mode** (identity block hidden — own requests; actions absent; reason + per-day states fully visible — FR-17 "matching FR-17 exactly"; this pre-builds 17-7's Cancel home). Embedded in the tab's ScrollView ⇒ pagination is a full-width `secondary` "Load more" button (first page 10; footer-spinner idiom doesn't apply to an embedded list; transient ActivityIndicator while fetching), rendered only while `nextCursor` exists. Empty: single muted line "No leave requests yet" (not an EmptyState — the apply row above is the CTA).

**D4 — Apply on behalf (FR-16): extracted shared form body, owner-stack screen (settled Q5 — no owner-mode props on the technician screen, no dual-stack routes).** `LeaveApplyFields.tsx` = presentational extraction of 17-5's Type/date-rows/count-chip/reason/notices (props-driven; `leaveApplyModel.ts` stays the shared brain; the technician `LeaveApplyScreen` re-renders identically — pinned by its existing tests). `ApplyOnBehalfScreen.tsx` (owner stack): `ScreenHeader` "Apply on behalf"; `SectionHead` "Team member" with a read-only selected-employee Card (Avatar + name + office + ghost "Change"); shared fields; pinned footer: `InlineError` slot + primary lg **"Approve"** (AC — born approved; never "Submit for approval").
**NO live working-days preview on this screen (wire-truth F3):** the whole `MeLeaveController` — including the preview GET — is `@Roles(TECHNICIAN)` and `RolesGuard` is exact-membership (no hierarchy): an owner JWT answers 403. The extracted count-chip slot is an OPTIONAL prop that this screen leaves empty (a muted one-liner "The working-days count appears once the request is submitted." may hold the rhythm — FE copy), and the count is discovered from the 201 view. The screen owns its own small state/submit hook — `useLeaveApply` is typed to the technician `LeaveApply` route and cannot be reused.
**Date plumbing (wire-truth F4):** `DatePickerParams.returnTo` (a closed union since 17-5) grows `'ApplyOnBehalf'`; the `ApplyOnBehalf` route params carry `pickedDate`/`context` with the same read-once-clear channel. **No server `today` exists here** — the From picker's UX floor is device-local today−7 as a convenience ONLY (commented as such); the authoritative ladders (`LEAVE_BEFORE_START_DATE`, `LEAVE_TOO_OLD`) are server-rendered verbatim on submit — never a client decision.
Submit: `POST /attendance/leave/on-behalf {employeeId, startDate, endDate?, part, reason}` + fresh `X-Idempotency-Key`; 201/replay ⇒ announce **"Leave applied for {name}"** ⇒ `navigate('OwnerLeave', { tab: 'all' })` (param merge pops back — landing on All makes the born-approved request visible; v1's "back to the queue" landed on Pending where it's invisible).
**Employee picker (settled Q2; wire-truth F1 corrected the data claim):** `EmployeePickerSheet` (OfficePickerSheet twin), data = the enrolments roster GET — which returns **EVERY** tenant technician including never-enrolled people (`NONE_STATE` rows; verified at enrolments.service.ts) — so the picker **filters to tracked rows: `attendanceStartDate != null`** (the ungated per-employee truth; NEVER `attendanceAccess` — module-gated, degrades — and NEVER `attendanceEnabled` — the tenant flag; the raw-truth rule). `officeName` is `string | null` on those rows: picker rows render a neutral fallback ("No office") and the `ApplyOnBehalf` route param is `officeName: string | null`. Sheet title "Choose team member", subtitle "Who is this leave for?", detent 0.6 scrollable, Avatar+name+office rows, `Search` input appears past 8 rows (client-side name filter), empty "No team members yet — enrol them from Attendance first."
**Error posture:** 17-5's rejection strings render verbatim; **`ATTENDANCE_NOT_TRACKED` on-behalf means the TARGET employee is untracked — NOT the owner: inline server message only, NO access-store refresh, form stays** (the tracked-only picker makes this rare but live). `ATTENDANCE_EMPLOYEE_NOT_FOUND` (404) ⇒ "This person isn't in your team anymore."

**D5 — Leave notification cards (FR-22/FR-27).** Registry gains role-keyed `leave-owner` / `leave-employee` classifications. `GenericNotificationCard` gains ONE additive optional `icon` prop (default `BellRing`) — a prop, not a new shell. Copy is FE-composed from payload data; single-day spans collapse to one date everywhere; **`reason` is ALWAYS in the `rejected`/`owner_revoked` payloads — null when empty: branch on `reason != null`, never on key presence** (verified at `notificationFor`); `owner_revoked`'s dates come from **`revokedDates[]`**, not the span; `cancelled_by_disable` reuses the 15-10 guarded attendance tap (a disabled employee tapping it must no-op — the tab no longer exists).

| Event | Recipient | Title | Message | Icon | Tap |
|---|---|---|---|---|---|
| `leave.applied` | owner | "{employeeName} applied for leave" | "{dates} · {n} working days" | CalendarOff | OwnerLeave `pending` |
| `leave.employee_cancelled` | owner | "{employeeName} cancelled leave" | "{dates}" — always (wire-truth F2: the payload carries `cancelledDates[]` but no span working-days, so "partly cancelled" is underivable without client-side span enumeration that weekly offs would corrupt; drop the branch) | CalendarX | OwnerLeave `all` |
| `leave.checkin_auto_cancel` | owner | "{employeeName} checked in on leave" | "Their leave on {leaveDate} was cancelled." | CalendarX | OwnerLeave `all` |
| `leave.applied_on_behalf` | employee | "Leave applied for you" | "{dates} · {n} working days" | CalendarOff | Attendance tab (guarded) |
| `leave.approved` | employee | "Leave approved" | "{dates} · {n} working days" | CheckCircle2 | Attendance tab (guarded) |
| `leave.rejected` | employee | "Leave rejected" | "{dates} — \"{reason}\"" with reason; "{dates}" without | XCircle | Attendance tab (guarded) |
| `leave.owner_revoked` | employee | "Leave revoked" | "{revokedDates} no longer count as leave" + " — {reason}" when present | Undo2 | Attendance tab (guarded) |

Unknown `leave.*` ⇒ humanized fallback (15-10 behaviour). **The leave-owner/leave-employee classifiers are ENUMERATED lists of exactly the 8 table events (wire-truth F6): `leave.pending_reminder` is a live 9th `leave.*` event (owner recipient, payload `[pendingCount]`, 19-1) — a prefix-keyed classifier would classify it and compose broken copy from missing fields. `pending_reminder` stays on the generic card.**

**D6 — Status chip table (settled Q4 — all existing DS keys, `tone="soft"`, icon + label always).** `requestStatusChip(status)` in `leaveStatusModel.ts` — one table for rows, sheet, split block:

| Status | Badge key | Icon | Label |
|---|---|---|---|
| pending | `scheduled` (amber) | Clock | "Pending" |
| approved | `done` (green) | CheckCircle2 | "Approved" |
| rejected | `cancelled` (red) | XCircle | "Rejected" |
| cancelled | `neutral` (gray) | CalendarX | "Cancelled" |
| revoked | `neutral` (gray) | Undo2 | "Revoked" |

Cancelled/Revoked are deliberately grey (self-own/non-events; red is reserved for decisions the employee must register — Rejected stays red); the family rule is satisfied by distinct icon + label.

**D7 — Service extensions (`attendanceLeave.ts`).** `listMyLeave({cursor?, limit?})`, `listOwnerLeave({status?, employeeId?, cursor?, limit?})` → `Paginated<LeaveRequestView & { employeeName?: string }>` (wire-truth F5: the FE envelope type is `Paginated<T>` in `src/services/api/pagination.ts` — `{data, nextCursor, hasMore}`, matching the wire; "PaginatedResponse" is BE-docs prose only. `employeeName` is list-only — never on write responses); `approveLeave(id)`, `rejectLeave(id, reason?)` → refreshed view; `applyOnBehalf(body, key)` → view. Approve/reject carry NO idempotency key (state-guarded own-retry, BE D7); on-behalf requires one. Wire truth: `reason` null-vs-present rule (D5); `totalDays` on every view.
