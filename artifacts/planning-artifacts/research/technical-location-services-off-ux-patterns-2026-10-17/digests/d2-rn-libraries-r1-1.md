## Leads

- The exact native error code expo-location throws from getCurrentPositionAsync when device services are off lives in expo/expo's native module — not in the TS layer or docs.
- iOS deep-linking to the system Location Services page (App-Prefs / prefs:root=Privacy&path=LOCATION URL scheme) and its App Review risk was not researched before budget ran out.
- react-native-permissions issue tracker may document how teams combine RESULTS.UNAVAILABLE with services-off detection — unread.
- react-native-geolocation-service's repo shows 230 commits but no releases and no rendered last-commit date; its actual last-commit date should be pulled via GitHub API to tighten the maintenance claim.
- The correct GitHub owner/repo for react-native-android-location-enabler (the dpa99c guess 404'd) needs resolving via npm's repository field.
